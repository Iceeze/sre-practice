# Отчёт по домашнему заданию № 1

## Доменная область

Приложение «Библиотека» ведёт каталог физических экземпляров книг и историю их выдачи читателям. Библиотекарь добавляет авторов, книги и читателей, оформляет выдачу и отмечает возврат. Каждая запись книги соответствует **одному физическому экземпляру**. Это позволяет однозначно запретить одновременную выдачу одного экземпляра двум читателям.

## Стек реализации

- **Бэкенд:** Python 3.12, FastAPI, Uvicorn, HTTP/1.1 и REST API с JSON.
- **Фронтенд:** HTML, CSS, JavaScript с `fetch`; сервер отдаёт статические файлы и страницу.
- **СУБД:** PostgreSQL 16; SQLAlchemy 2 для работы с данными, `psycopg` для подключения.
- **Изменение схемы БД:** Alembic.
- **Управление зависимостями:** `uv`, `pyproject.toml`.
- **Запуск:** Docker и Docker Compose; Python-зависимости внутри образа устанавливаются через `uv sync --locked`.

Браузер обращается к `/api/...` по HTTP. Бэкенд читает и изменяет данные в PostgreSQL. Интерфейс и API доступны через один порт, поэтому отдельный сервер фронтенда и настройка CORS не требуются.

## Основные сущности и связи

| Сущность | Поля | Смысл |
|---|---|---|
| **Автор** | `id`, `first_name`, `last_name` | У автора может быть много книг. У книги ровно один автор; соавторство в первой версии не моделируется. |
| **Книга** | `id`, `title`, `isbn`, `publication_year`, `inventory_number`, `author_id` | `isbn` обязателен, но не уникален для разных экземпляров одного издания. `inventory_number` обязателен и уникален. Год издания необязателен. |
| **Читатель** | `id`, `first_name`, `last_name`, `phone` | Телефон обязателен, уникален и записывается в международном формате: `+` и 8–15 цифр. |
| **Выдача** | `id`, `book_id`, `reader_id`, `issued_on`, `due_on`, `returned_on` | Связывает экземпляр книги с читателем. Пустой `returned_on` означает активную выдачу. |

Связи: `Автор 1:N Книга`, `Книга 1:N Выдача`, `Читатель 1:N Выдача`. Для всех четырёх сущностей доступны создание, получение списка и одной записи, обновление и удаление через `POST`, `GET`, `PUT`, `DELETE`. В интерфейсе эти же действия доступны через формы и кнопки.

Проверки выполняются на уровне API и PostgreSQL: срок возврата и фактическая дата возврата не могут быть раньше даты выдачи; частичный уникальный индекс `uq_loans_one_active_per_book` разрешает только одну активную выдачу на экземпляр. Внешние ключи запрещают удаление автора, книги или читателя, если на них ссылаются другие записи. Статус «просрочена» вычисляется из даты возврата, не дублируется в БД.

## Соответствие методологии 12 факторов

| Фактор | Реализация и аргументация |
|---|---|
| **I. Кодовая база** | Бэкенд, фронтенд, миграции, Dockerfile и Compose находятся в одной кодовой базе. Один исходный код используется для разных развёртываний; настройки меняются через окружение. В проекте есть `.gitignore` для исключения локальных секретов и временных файлов. |
| **II. Зависимости** | Прямые зависимости указаны в `pyproject.toml`, полное дерево с точными версиями сохранено в `uv.lock`. `uv sync --locked` создаёт изолированное окружение и воспроизводит его в Docker. Приложение не рассчитывает на глобально установленные библиотеки Python. |
| **III. Конфигурация** | Адрес БД читается из `DATABASE_URL`, порт — из `PORT`, число рабочих процессов — из `WEB_CONCURRENCY`. Реквизиты БД Compose получает из переменных `POSTGRES_*`. Файл `.env.example` содержит только пример локальной конфигурации, а `.env` исключён из Git и Docker-образа. |
| **IV. Сторонние службы** | PostgreSQL — подключаемый ресурс; приложение получает адрес через `DATABASE_URL` и не привязано к конкретному хосту БД. Постоянные данные находятся в PostgreSQL, а не в контейнере приложения. |
| **V. Сборка, релиз, запуск** | Сборка образа выполняется по `Dockerfile`. Отдельный одноразовый процесс `migrate` применяет версионированную миграцию перед запуском процесса `app`; сервер при старте схему не меняет. Образ затем запускается с конфигурацией окружения. |
| **VI. Процессы** | HTTP-процесс не хранит пользовательские данные и сеансы в памяти или локальных файлах; все записи находятся в PostgreSQL. Любой новый рабочий процесс может обработать следующий запрос. |
| **VII. Привязка к порту** | Uvicorn самостоятельно слушает HTTP-порт `PORT` на `0.0.0.0`; ему не нужен внешний веб-сервер для работы API. |
| **VIII. Параллелизм** | `WEB_CONCURRENCY` управляет числом процессов Uvicorn. Процессы не разделяют локальное состояние, а обращаются к общей БД. Для развёртывания на нескольких узлах перед ними можно поставить балансировщик; конфигурация единственного локального порта в Compose предназначена для учебного запуска. |
| **IX. Быстрый запуск и завершение** | Сервер не выполняет миграции и долгую инициализацию при старте. Uvicorn обрабатывает сигнал завершения, а сессия БД закрывается после запроса. Проверки `/health/live` и `/health/ready` позволяют отличить работающий процесс от готового к запросам. |
| **X. Одинаковость сред** | Один Dockerfile и один `uv.lock` используются во всех окружениях. Compose поднимает PostgreSQL той же основной версии, которую можно использовать при другом развёртывании. Различаются только переменные окружения и адрес подключаемой БД. |
| **XI. Журналы** | Uvicorn пишет сообщения и ошибки в стандартные потоки; приложение не управляет файлами журналов. Их сбор и хранение выполняет среда запуска, например Docker. |
| **XII. Административные задачи** | Alembic запускается одноразовой командой в том же образе и с той же конфигурацией БД, что и сервер. Для ручного применения доступно `docker compose run --rm migrate`. |

## Запуск и проверка

Команда `docker compose up --build -d` поднимает БД, применяет миграцию и запускает приложение. Интерфейс доступен по `http://localhost:8000/`, документация API — по `http://localhost:8000/docs`. После смены `PORT` адрес меняется соответственно. Последовательность проверки: создать автора, книгу, читателя, выдать книгу, убедиться, что повторная выдача того же экземпляра отклоняется, отметить возврат, затем снова оформить выдачу.
