# Отчёт по домашнему заданию № 2

Пошаговая инструкция по запуску приложения в minikube, масштабированию и демонстрации интерфейса приведена в [k8s/README.md](k8s/README.md).

## Приложение и окружение

Приложение «Библиотека» предназначено для учёта авторов, физических экземпляров книг, читателей и выдач. Сервер реализован на FastAPI, веб-интерфейс — на HTML, CSS и JavaScript. Данные хранятся в PostgreSQL, схема базы обновляется миграциями Alembic.

Для развёртывания использован локальный кластер minikube с профилем `sre-docker`, драйвером Docker и средой выполнения контейнеров Docker. Образ `sre-library:1.0.0` собран по [Dockerfile](Dockerfile). Он содержит сервер, статические файлы интерфейса и миграции. Для базы данных используется готовый образ `postgres:16.8-alpine`.

Команды подготовки в PowerShell:

```powershell
minikube start -p sre-docker --driver=docker --container-runtime=docker
minikube -p sre-docker docker-env --shell powershell | Invoke-Expression
docker build -t sre-library:1.0.0 .
```

После переключения через `docker-env` сборка выполняется в Docker-демоне выбранного кластера. В манифестах приложения и миграций указано `imagePullPolicy: Never`: используется локально собранный образ.

## Использованные абстракции Kubernetes

Манифесты находятся в каталоге [k8s](k8s/).

| Абстракция | Ресурс в проекте | Назначение |
|---|---|---|
| **Namespace** | `library` | Объединяет ресурсы приложения в отдельном пространстве имён. Указан во всех манифестах приложения. |
| **ConfigMap** | `library-config` | Хранит обычные настройки: имя пользователя и базы PostgreSQL, порт HTTP-сервера и число процессов Uvicorn. Значения передаются контейнерам через переменные окружения. |
| **Secret** | `library-secret` | Хранит пароль PostgreSQL и строку подключения `DATABASE_URL`, которую используют сервер и миграции. |
| **Deployment** | `library` | Управляет двумя репликами HTTP-приложения. Стратегия `RollingUpdate` предусматривает обновление с одной дополнительной репликой (`maxSurge: 1`) и без планового уменьшения количества доступных реплик (`maxUnavailable: 0`). |
| **Deployment** | `postgres` | Управляет одной репликой PostgreSQL. Стратегия `Recreate` при обновлении сначала завершает старый Pod, затем создаёт новый, чтобы экземпляры БД не работали одновременно с одним каталогом данных. |
| **ReplicaSet** | Создаются контроллерами Deployment | Поддерживают заданное количество Pod приложения и БД. Отдельные манифесты ReplicaSet не нужны: ими управляют Deployment. |
| **Pod** | Создаются для приложения, PostgreSQL и миграций | Содержат запускаемые контейнеры, их настройки, проверки здоровья и подключения томов. В каждом Pod этого проекта находится один контейнер. |
| **Service** | `library`, `postgres` | Предоставляют стабильные сетевые имена и порты внутри кластера. По меткам выбирают Pod, к которым нужно направлять соединения. Оба сервиса имеют тип `ClusterIP`. |
| **Job** | `library-migrate` | Однократно выполняет `alembic upgrade head` перед запуском приложения. Использует тот же образ, что и сервер, но с другой командой. Заданы `backoffLimit: 6`, `activeDeadlineSeconds: 300` и `restartPolicy: Never`. |
| **PersistentVolumeClaim** | `postgres-data` | Запрашивает 1 GiB постоянного хранилища с режимом `ReadWriteOnce`. Том подключается в контейнер PostgreSQL по пути `/var/lib/postgresql/data`; файлы БД находятся в подкаталоге `pgdata`. |
| **PersistentVolume и StorageClass** | Предоставляются инфраструктурой minikube | Стандартный StorageClass обеспечивает выделение тома для PVC. Отдельный манифест PV в проекте не создаётся. Данные сохраняются при пересоздании Pod PostgreSQL. |

Цепочка управления постоянно работающими компонентами:

```text
Deployment library  → ReplicaSet → 2 Pod FastAPI
Deployment postgres → ReplicaSet → 1 Pod PostgreSQL
Job library-migrate → Pod миграций
```

## Взаимодействие компонентов приложения

### Веб-интерфейс и HTTP-сервер

FastAPI отдаёт HTML-страницу по пути `/`, статические файлы по `/static/` и обрабатывает REST-запросы по `/api/`. JavaScript в браузере вызывает API через `fetch` с относительными адресами.

Service `library` выбирает Pod с меткой `app: library` и направляет соединения со своего порта `80` на порт `8000` готовых Pod. Обе реплики работают с общей базой данных и не хранят пользовательские записи локально.

### Сервер и PostgreSQL

Сервер получает `DATABASE_URL` из Secret. В строке подключения указан хост `postgres` — имя Service базы данных в namespace `library`, которое разрешается через DNS кластера. Service выбирает Pod с меткой `app: library-postgres` и предоставляет доступ к PostgreSQL на порту `5432`.

FastAPI использует SQLAlchemy и драйвер `psycopg` для чтения и изменения данных. Браузер взаимодействует только с HTTP API и напрямую к PostgreSQL не подключается.

```text
Клиент внутри кластера
        │ HTTP, порт 80
        ▼
Service library
        │ порт 8000
        ├───────────────┐
        ▼               ▼
   Pod FastAPI № 1  Pod FastAPI № 2
        │               │
        └───────┬───────┘
                │ SQL-соединение, порт 5432
                ▼
         Service postgres
                │ порт 5432
                ▼
         Pod PostgreSQL
                │ запись и чтение файлов
                ▼
        PVC postgres-data → постоянный том
```

### Миграции и порядок запуска

Job `library-migrate` также подключается к `postgres:5432` по `DATABASE_URL` из Secret. Он создаёт и обновляет таблицы до запуска HTTP-приложения. Миграции не выполняются в каждой реплике сервера, поэтому их запуск отделён от масштабирования приложения.

Порядок развёртывания:

1. Создать Namespace, ConfigMap и Secret.
2. Создать PVC, Service и Deployment PostgreSQL, дождаться готовности БД.
3. Создать Job миграций и дождаться его успешного завершения.
4. Создать Deployment и Service приложения; дождаться готовности реплик.

Deployment не ожидает завершения Job автоматически. Перед запуском приложения ожидание выполняется явно:

```powershell
kubectl --context sre-docker -n library wait --for=condition=complete job/library-migrate --timeout=300s
```

### Доступ с локального компьютера

Для открытия приложения из Windows используется проброс порта:

```powershell
kubectl --context sre-docker -n library port-forward service/library 8000:80
```

После этого интерфейс доступен по адресу `http://localhost:8000/`, а документация API — по `http://localhost:8000/docs`. Команда выбирает Pod по Service и создаёт туннель к его порту `8000`. Такой локальный доступ не проверяет распределение трафика между двумя репликами через ClusterIP.
