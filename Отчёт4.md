# Отчёт по домашнему заданию №4. Экспорт и сбор метрик

## Приложение и стек

Приложение «Библиотека» предназначено для учёта физических экземпляров книг, авторов, читателей, выдач и возвратов. Оно развёрнуто в minikube, профиль `sre-docker`.

| Компонент | Реализация |
|---|---|
| Сервер приложения | Python 3.12, FastAPI 0.115.12, Uvicorn 0.34.2 |
| Доступ к данным и миграции | SQLAlchemy 2.0.40, psycopg 3.2.6, Alembic 1.15.2 |
| База данных | PostgreSQL 16.8 |
| Интерфейс | HTML, CSS, JavaScript |
| Метрики HTTP / FastAPI | prometheus-fastapi-instrumentator 7.1.0 |
| Метрики Python и бизнес-счётчики | prometheus-client 0.22.1 |
| Метрики PostgreSQL | prometheuscommunity/postgres-exporter v0.18.1 |
| Хранилище и сборщик метрик | VictoriaMetrics Single v1.154.0, Helm-chart victoria-metrics-single 0.49.0 |

Версии Python-зависимостей зафиксированы в `pyproject.toml` и `uv.lock`. Приложение работает в двух репликах в namespace `library`. PostgreSQL с exporter размещён в том же namespace, VictoriaMetrics — в namespace `metrics`.

## Схема сбора

Используется Pull-модель: VictoriaMetrics Single автоматически обнаруживает Pod и периодически выполняет HTTP-запросы к их exporter. Интервал сбора — 15 секунд.

Сбор включён в `k8s/metrics/guide-vmsingle-values.yaml` через `server.scrape.enabled`. Отдельный vmagent не развёрнут: его функцию выполняет встроенный scraper VictoriaMetrics.

## Экспорт метрик приложения

В `src/app.py` библиотека `prometheus-fastapi-instrumentator` подключена к FastAPI через `Instrumentator(...).instrument(app)`. Она автоматически собирает:

- `http_requests_total` — количество запросов с методом, шаблоном маршрута и кодом ответа;
- `http_request_duration_seconds` и `http_request_duration_highr_seconds` — распределение длительности запросов;
- `http_request_size_bytes` и `http_response_size_bytes` — размеры запросов и ответов;
- `http_requests_inprogress` — количество запросов в обработке.

В labels используются шаблоны вида `/api/books/{item_id}`, неизвестные пути группируются в `none`. Проверки `/health/*` исключены из HTTP-метрик. Имена читателей, телефоны и ID записей не добавляются в labels.

Готовые collectors `prometheus-client` экспортируют `python_info`, статистику GC `python_gc_*`, а в Linux-контейнере — показатели процесса, в том числе `process_cpu_seconds_total` и `process_resident_memory_bytes`.

В `src/metrics.py` при запуске FastAPI поднимается HTTP-exporter на отдельном порту `8001`; при остановке приложения сервер корректно завершается. Endpoint `/metrics` доступен без авторизации внутри кластера по Pod IP. Service приложения предоставляет только основной HTTP-порт `80 → 8000`, а порт метрик через него не публикуется. На основном порту маршрут `/metrics` отсутствует.

Exporter поддерживает формат OpenMetrics при заголовке `Accept: application/openmetrics-text; version=1.0.0`, ответ имеет соответствующий `Content-Type` и завершается `# EOF`. Также доступен текстовый формат Prometheus для сбора VictoriaMetrics.

## Реализованные бизнес-метрики

Все четыре метрики имеют тип **Counter** и объявлены в `src/metrics.py`. Они увеличиваются в сервисах после успешного сохранения данных в БД.

| Метрика | Событие | Реализация |
|---|---|---|
| `library_books_created_total` | Добавлен новый физический экземпляр книги | `BookService.create`, `src/services/books.py` |
| `library_readers_registered_total` | Зарегистрирован новый читатель | `ReaderService.create`, `src/services/readers.py` |
| `library_loans_created_total` | Создана запись выдачи книги | `LoanService.create`, `src/services/loans.py` |
| `library_loans_returned_total` | Активная выдача переведена в возвращённую: `returned_on` изменён с `NULL` на дату | `LoanService.update`, `src/services/loans.py` |

## Экспорт метрик PostgreSQL

В `k8s/03-postgres.yaml` к Pod БД добавлен контейнер `postgres-exporter`. Контейнеры используют общую сеть, поэтому exporter подключается к PostgreSQL по `127.0.0.1:5432`. Имя БД и пользователь берутся из ConfigMap `library-config`, пароль — из Secret `library-secret`.

Exporter отдаёт HTTP-метрики на `9187/metrics`. Для него заданы readiness/liveness probes, запуск без root и ограничения ресурсов. Доступ к файлам БД не требуется. PostgreSQL хранит данные на PVC `postgres-data`. Метрики VictoriaMetrics хранятся на отдельном PVC в namespace `metrics`.

Используются готовые метрики: `pg_up` — доступность БД для exporter, `pg_stat_database_numbackends` — количество подключений, `pg_stat_database_xact_commit` — завершённые транзакции, а также статистика блокировок и таблиц. `up=1` подтверждает успешный HTTP-сбор; для проверки подключения к БД отдельно проверяется `pg_up=1`.

## Service discovery и манифесты

В шаблоны Pod Deployment приложения и PostgreSQL добавлены аннотации:

```yaml
prometheus.io/scrape: "true"
prometheus.io/port: "8001"  # Для postgres-exporter: "9187"
prometheus.io/path: "/metrics"
```
