## Манифесты приложения

Все девять ресурсов из `00-namespace.yaml`–`05-app.yaml` приняты командой
`kubectl --context minikube apply --dry-run=server` на Kubernetes v1.37.0.
Для namespaced-ресурсов только в потоке проверки namespace заменялся на временный `sre-seminar`;
в файлах остался `library`. Это позволило проверить манифесты без создания ресурсов приложения.

**Развёртывание приложения в Kubernetes не выполнялось:** настройка `docker-env` и загрузка
образа в minikube оставлены пользователю. Проверка сервера Kubernetes подтверждает корректность
схемы ресурсов, но не заменяет проверку реального запуска, PVC и доступа к БД внутри кластера.
После загрузки образа выполните последовательность из [README.md](README.md).

## Практика семинара

Существующий профиль minikube запущен с Docker driver; runtime внутри узла — containerd 2.3.4.
Все упражнения выполнены в созданном для них namespace `sre-seminar`.

| Проверка | Фактический результат |
|---|---|
| Pod | `my-pod` Ready; `nginx -v` → `nginx/1.12.2` |
| ReplicaSet | Масштабирование до 3; после удаления Pod создан новый; READY 3 |
| Deployment | 2 реплики; успешное обновление `nginx:1.12` → `nginx:1.13`; две ревизии |
| ConfigMap | nginx принял конфигурацию, HTTP-ответ содержит имя Pod |
| Secret | `TEST_1` внутри контейнера равен учебному значению `asdf` |
| Service | Два адреса в EndpointSlice; запрос из BusyBox вернул имя Pod nginx |
| port-forward | Запрос с компьютера к `127.0.0.1:18080` вернул HTTP 200 и имя Pod |
| Job | `hello` Complete 1/1; в логе дата и `Hello from the Kubernetes cluster` |
| CronJob | Автоматически созданные по расписанию Jobs завершились Complete 1/1 |
| DaemonSet | После обновления образа `node-exporter` DESIRED/CURRENT/READY = 1/1/1; слушает порт 9101 |

Первоначальный `node-exporter:v0.16.0` не загрузился: containerd сообщил, что Docker Schema 1
больше не поддерживается. В копии примера образ обновлён до `v1.9.1`, флаги приведены
к поддерживаемым именам; повторный запуск успешен. Также обновлены API CronJob и метка ОС узла.
Оригиналы в Downloads не менялись.

После практики namespace `sre-seminar` удалён, включая CronJob, чтобы задания не продолжали запускаться.
Minikube оставлен запущенным для следующих шагов пользователя; активный контекст kubectl — `minikube`.
