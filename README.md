# Библиотека

Небольшое клиент-серверное приложение для учёта физических экземпляров книг и их выдачи читателям. Фронтенд написан на HTML, CSS и JavaScript, сервер — на FastAPI, данные хранятся в PostgreSQL.

## Быстрый запуск

Нужны Docker и Docker Compose. Из корня проекта:

```bash
docker compose up --build -d
```

Откройте приложение: <http://localhost:8000/>. Документация REST API: <http://localhost:8000/docs>. При изменении `PORT` в `.env` используйте указанный порт.

При первом запуске Compose поднимает PostgreSQL, применяет миграцию Alembic и запускает сервер. Данные БД сохраняются в именованном томе `pgdata`. Для остановки используйте `docker compose down` — эта команда сохраняет том и данные.

## Зависимости и локальный запуск через uv

Проект использует [uv](https://docs.astral.sh/uv/). Перед локальным запуском установите uv и откройте новый терминал. Прямые зависимости объявлены в `pyproject.toml`, точные версии всех зависимостей записаны в `uv.lock`. Оба файла входят в исходный код.

```bash
uv sync --locked
```

Для запуска Python-команд на компьютере нужен доступный PostgreSQL и переменная окружения `DATABASE_URL`. Compose публикует БД только на `127.0.0.1:55433` (порт меняется через `DB_PORT`). Добавьте `DATABASE_URL` в свой `.env` по образцу `.env.example`; если изменяли `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` или `DB_PORT`, укажите те же значения в URL. Затем выполните:

```bash
uv run --locked --env-file .env alembic upgrade head
uv run --locked --env-file .env uvicorn src.main:app --host 0.0.0.0 --port 8000
```

Чтобы добавить или обновить зависимость, используйте `uv add <package>` или измените `pyproject.toml` и выполните `uv lock`. Команда `uv sync --locked` проверит, что lock-файл соответствует описанию проекта. В Docker зависимости также устанавливаются через `uv sync --locked`.

Можно скопировать `.env.example` в `.env` и изменить порт и реквизиты локальной БД. Значения в `docker-compose.yaml` предназначены только для локальной разработки. Для другого окружения передайте собственные значения через переменные окружения; файл `.env` не добавляйте в систему контроля версий.

## Порядок работы

1. Создайте автора.
2. Создайте книгу, выбрав автора. Одна запись книги соответствует одному физическому экземпляру.
3. Создайте читателя. Номер телефона указывайте в международном формате, например `+79991234567`.
4. Оформите выдачу, выбрав книгу и читателя.
5. Нажмите «Вернуть» у выдачи, чтобы отметить возврат.

Несколько экземпляров могут иметь одинаковый ISBN; их различают инвентарные номера. Книгу нельзя выдать двум читателям одновременно. Автора, книгу или читателя со связанными записями нельзя удалить, пока эти связи существуют.

## API

Для каждого ресурса `authors`, `books`, `readers`, `loans` доступны:

| Метод | Путь | Действие |
|---|---|---|
| `GET` | `/api/{resource}` | Список |
| `GET` | `/api/{resource}/{id}` | Одна запись |
| `POST` | `/api/{resource}` | Создание |
| `PUT` | `/api/{resource}/{id}` | Полное обновление |
| `DELETE` | `/api/{resource}/{id}` | Удаление |

Ошибки валидации возвращаются с кодом `422`, отсутствие записи — `404`, нарушение ограничений БД — `409`. Эндпоинты `/health/live` и `/health/ready` можно использовать для проверок процесса и подключения к БД.

Пример создания автора:

```bash
curl -X POST http://localhost:8000/api/authors \
  -H 'Content-Type: application/json' \
  -d '{"first_name":"Лев","last_name":"Толстой"}'
```

## Миграции

Миграции хранятся в `migrations/versions`. Для генерации новой миграции из моделей используйте доступную БД, находящуюся на текущей ревизии:

```bash
uv run --locked --env-file .env alembic revision --autogenerate -m "описание изменения"
```

Alembic сравнивает модели с реальной схемой БД, поэтому `DATABASE_URL` обязательна. Начальную миграцию нужно генерировать на пустой БД; последующие — на БД после применения предыдущих миграций. Сгенерированный файл следует просмотреть перед применением. Для ручного применения в запущенном окружении:

```bash
docker compose run --rm migrate
```

Миграция выполняется отдельным процессом до запуска сервера. Сервер не создаёт таблицы при старте.

## Структура

- `src/main.py` — сборка приложения, обработка ошибок и проверка состояния;
- `src/routers/` — REST маршруты авторов, книг, читателей и выдач;
- `src/services/` — общий CRUD в `base.py` и правила каждой сущности в отдельных сервисах;
- `src/dependencies.py` — создание сервисов для обработчиков запросов;
- `src/models.py`, `src/schemas.py` — модели БД и проверка входных данных;
- `src/static/` — веб-интерфейс;
- `migrations/` — миграции БД;
- `pyproject.toml`, `uv.lock` — зависимости и их зафиксированные версии;
- `docker-compose.yaml`, `Dockerfile` — запуск окружения;

### Как устроен фронтенд

Начните чтение с `src/static/app.js`: он хранит загруженные данные и текущий раздел,
подключает события и описывает действия пользователя — сохранение, удаление и возврат книги.

| Файл в `src/static/` | Ответственность |
|---|---|
| `app.js` | Состояние страницы и последовательность действий |
| `api.js` | HTTP-запросы и обработка ответов сервера |
| `resources.js` | Поля, подписи и столбцы четырёх разделов |
| `form.js` | Построение формы и чтение введённых значений |
| `table.js` | Построение таблицы и кнопок действий |

Например, при сохранении `app.js` получает данные из `form.js`, передаёт их в `api.js`,
загружает обновлённые списки и вызывает функции отображения. Форма и таблица получают
данные аргументами. Таблица вызывает обработчики из `app.js`, когда пользователь нажимает кнопку.

JavaScript подключён через `type="module"`: браузер загружает файлы по `import`.
Сборщик и дополнительные зависимости не требуются. Открывайте интерфейс через HTTP-сервер приложения.
